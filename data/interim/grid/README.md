# Grid data (interim)

Cleaned Catalunya tables built from the raw files in `data/raw/grid/`. Contributed by Hsiang Wei on 2026-10-22, copied from https://github.com/hhw2002/data-driven-challenge-project (`data/clean/catalunya/`).

These are not outputs of this repository's pipeline: they were produced by the scripts in that repository's `scripts/` folder (named below), and they do not follow this repository's data contract yet (column names are not `snake_case`, there is no `node_id`). All files sit directly in this folder; where the text below says `<region>`, read `catalunya`. Paths `data/raw/...` below refer to `data/raw/grid/...` here. The interactive maps mentioned below live in the other repository's `docs/` folder and are not copied.

e-distribución capacity data (see `data/raw/README.md`), filtered to Catalunya. Generated by `scripts/filter_edistribucion.py` from the 2026-09 raw snapshot.

## catalunya/

- `generacion_catalunya.csv` — 357 rows, 201 unique substations.

**Not copied here:** `demanda_catalunya.csv`, which overlaps with `data/raw/demand/edistribucion_demand_capacity_catalonia_2026-10.csv`. `nodos_catalunya.csv` was still built from the 2026-09 demand file, so its `edis_dem | ` columns are one month older than that demand file.

**Column changes from raw:** the source file repeats `Provincia` and `Municipio` twice (once as an INE numeric code, once as a human-readable label). These are renamed to disambiguate: `provincia_codigo`/`municipio_codigo` (code) vs. `provincia`/`municipio` (label). Two columns are added — `lat`, `lon` (WGS84) — converted from `Coordenada UTM X`/`Coordenada UTM Y` via `scripts/geo_utils.py`, assuming the source UTM values are ETRS89 / UTM zone 30N (EPSG:25830, see that script's docstring for why). All other columns are unchanged — see `data/raw/README.md` for field meanings.

**Not yet done:** demand and generation are still two separate files per region (not joined). Re-run `scripts/filter_edistribucion.py` whenever a new raw snapshot is downloaded — it overwrites these CSVs.

## REE transmission-node capacity

Each region folder also has `ree_demanda_<region>.csv` and `ree_generacion_<region>.csv`, generated by `scripts/filter_ree_transporte.py` from the 2026-10 REE snapshot (see `data/raw/README.md`). One row per transmission node: Catalunya 117.

**Column changes from raw:** the multi-row merged header is flattened into one name per column, levels joined with ` | ` (e.g. `MARGEN DE CAPACIDAD DE ACCESO TOTAL | Almacenamiento | MPE [MW]`). Two columns are added — `nombre_nudo` and `tension_kv` — split from `Nombre y tensión del nudo`. Columns holding only numbers and `NA`/`N/A` markers are stored as numeric, with the markers as empty cells. No columns are dropped; definitions are in the raw workbook's `Leyenda` sheet.

**Not yet done:** no coordinates for the transmission nodes.

## Merged node table

`nodos_<region>.csv` in each region folder, generated by `scripts/merge_nodes.py`. One row per e-distribución node (substation × voltage level): Catalunya 357. Each row has the node's demand and generation capacity from e-distribución plus the situation of its upstream transmission node from REE, linked through e-distribución's `Nudo Afección RdT`.

**Every column name starts with its source:**

| Prefix | Source |
|---|---|
| `edis \| ` | e-distribución, identical in its demand and generation files (taken from the demand file) |
| `edis_dem \| ` | e-distribución demand file |
| `edis_gen \| ` | e-distribución generation file |
| `ree \| ` | REE, identical in its demand and generation files |
| `ree_dem \| ` | REE demand file |
| `ree_gen \| ` | REE generation file |

The one unprefixed column, `enlace_ree`, is added by the script and says how the row was linked to REE:

| Value | Meaning | Catalunya |
|---|---|---|
| `exacto` | upstream name found as-is in REE | 352 |
| `nombre corregido` | found after a spelling fix (`TANGER (CATALUÑA) 220` → `TANGER CATALUÑA 220`) | 2 |
| `dos nudos` | e-distribución names two upstream nodes; REE columns are left empty | 3 |
| `sin nudo` | upstream is `A determinar`; REE columns are left empty | 0 |

**Things to know before using it:**
- The two sources are a month apart: e-distribución 2026-09, REE 2026-10-01.
- The REE values describe the upstream transmission node, so they repeat on every e-distribución node under it. Do not sum `ree_*` columns across rows.
- Only a selection of REE columns is carried over (margins, available capacity, limiting criteria, reasons, tender flags — see `REE_SECTIONS` in the script). The rest are in `ree_*_<region>.csv`, joinable on `ree | Nombre y tensión del nudo`.
- REE nodes that no e-distribución node points to are not in this table: 44 of 117 in Cataluña. Almost all of these have no connection positions towards the distribution network in REE's own data (41 of the 44).
- The upstream node can be in a neighbouring region (17 Catalunya rows hang off nodes in Aragón).
- `edis | municipio` comes from the demand file. The generation file differs only in apostrophe style and in the name of one municipality (C.ARO).

## Substation sites

`subestaciones_<region>.csv` in each region folder, generated by `scripts/classify_substations.py`. One row per physical substation site, classified into:

| `categoria` | Meaning | Catalunya |
|---|---|---|
| `1 TSO` | REE transmission substation with no e-distribución substation at the same spot | 28 |
| `2 TSO+DSO` | REE and e-distribución substations at the same spot | 70 |
| `3 DSO` | e-distribución substation with no REE substation at the same spot | 131 |

A TSO site is one REE `Código de subestación` (it can hold both a 400 kV and a 220 kV node); a DSO site is one e-distribución `Subestación` code (it can hold several voltage levels). The two code systems never overlap, so "same spot" is judged from distance, name and the upstream link — see the script's docstring for the rules.

**Unprefixed columns** (added by the script):
- `confianza` — for category 2: `alta` (≤ 300 m apart, TSO located in OSM by name, plus name or upstream agreement), `media` (TSO located only through the upstream link, or not located at all but name and upstream agree). `a revisar` marks a site that might pair with another but is too far apart to decide automatically; it stays in its own category until reviewed (record the decision in `MANUAL_PAIRS` in the script).
- `distancia_m` — metres between the e-distribución point and the TSO site's OSM location.
- `nombre_similar`, `aguas_arriba` — whether the names match, and whether e-distribución lists this TSO site as upstream.
- `lat`, `lon`, `fuente_coordenadas` — one location per site: the e-distribución point if the site has one (`edis`), else the OSM point (`osm`), else empty.

**Things to know before using it:**
- Only e-distribución is covered on the DSO side. A `1 TSO` site may still have another distributor (see the CNMC layers below) or a private customer substation on site.
- `osm | ubicado_por` says how the TSO site was located: `nombre` (OSM name matches), `aguas arriba` (the unclaimed OSM 220/400 kV substation next to an e-distribución site that lists it as upstream), or empty (not located: 17 TSO-only sites have no coordinates).
- Pending review: VANDELLOS (432 m from REE's Vandellòs substation) — name and upstream agree but the distance is too large.

| Layer | Catalunya |
|---|---|
| `generacion_transporte` (REE) | 117 |
| `demanda_transporte` (REE) | 117 |
| `generacion_distribucion` (all distributors) | 393 (14 operators) |
| `demanda_distribucion` (all distributors) | 395 (15 operators) |

**Region selection:** by `PROVINCIA`, dropping rows whose point lies more than ~10 km outside the region (removes TORRENTE and LA PEREDA, mislabelled as Girona). If a distribution point is far outside but its UTM values land inside when read as zone 31N, the corrected point is kept and `coordenadas_corregidas` is `True` (SE PLA ESTANY in Catalunya).
